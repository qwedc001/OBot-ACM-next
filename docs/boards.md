# HydroOJ 训练榜单

Peeper Board Generator 以 Git submodule 接入 `third-party/peeper-board-generator`，固定提交 `e5764481984ce7f4291e0c17c064815f18bbb08f`（v1.2.5）。上游源码保持原样，榜单沿用其样式。初始化仓库时执行：

```sh
git submodule update --init --recursive
uv sync --extra render
```

升级生成器需要明确选择提交并更新主仓库的 gitlink，同时运行榜单渲染测试；不在启动时自动更新依赖。

## 绑定配置

私聊发送 `/board bind xxxOJ`，打开返回的一次性网页，填写 HydroOJ 公网 HTTPS 地址、管理员名称和密码。支持 `https://oj.example.com/d/team` 这样的域路径。配置名不区分大小写，支持字母、数字、汉字、下划线和短横线。

链接默认有效 15 分钟，打开和预览不会消耗链接；提交成功后失效。重新获取同名链接会作废之前的链接。登录验证失败可以重试，最多五次。个人与各群配置分别保存，查询不会回退到别人的配置。

群聊由群主、群管理员或机器人超管发起绑定。网页验证后先保存待确认配置；原发起人须在原群发送 `/board confirm xxxOJ` 才生效，确认时重新检查群管理权限。这样群中可见的链接本身不能直接替换群配置。普通群员可以查询已绑定的榜单。

网页还可设置排除 UID、排除某日期前注册的用户，以及是否显示打星用户。默认不排除用户，显示打星用户。账号必须具有读取训练记录和运行 Hydro 管理脚本的权限；当前支持密码登录，不支持额外的登录验证码或双因素认证流程。

## 使用

| 指令 | 作用 |
| --- | --- |
| `/board` | 根据当前场景和权限展示用法 |
| `/board list` | 列出当前对话可用配置 |
| `/board today [配置名]` | 今日榜单 |
| `/board yesterday [配置名]` | 昨日总榜 |
| `/board history YYYY-MM-DD [配置名]` | 指定日期的历史榜单 |
| `/board verdict WA [配置名]` | 今日指定评测类型的榜单 |
| `/board user id 用户ID [配置名]` | 私聊查询用户资料与今日提交统计 |
| `/board user name 用户名 [配置名]` | 私聊模糊匹配名字查询；含空格的名字使用引号 |
| `/board version` | 上游生成器版本 |
| `/board push on或off [配置名]` | 管理者开启或关闭本对话的每日推送 |
| `/board push status [配置名]` | 管理者查看推送开关、任务注册及下次执行时间 |
| `/board push test [配置名]` | 管理者通过主动接口测试发送昨日榜单，会实际发送一条榜单 |
| `/board starred [on或off或toggle] [配置名]` | 管理者开启、关闭或切换打星用户显示；省略状态默认切换 |
| `/board unbind 配置名` | 管理者解除本对话绑定并清除相关缓存 |

评测类型包括 AC、WA、TLE、MLE、OLE、RE、CE、SE、FE、HKD。同一对话绑定多个配置时，查询需要指定名称。正式路径为 `/cp.board`，`/board` 是短别名；这是显式业务入口，不会自动注册其他目录或 QQ 指令面板。`/help cp` 可以查看模块说明。

`/board starred off xxxOJ` 隐藏打星用户，`/board starred on xxxOJ` 恢复显示；只有一个配置时可直接 `/board starred` 切换。设置持久保存在当前个人或群配置中，立即作用于下一次生成和每日推送，不需要重新绑定，也不会删除历史快照。

推送开关和目标保存在数据库，重启后仍有效。两个固定任务在每次启动时重新注册，不需要持久化绑定 Python 对象的调度任务；服务离线错过的执行不会自动补发。主动发送失败记录异常类型、HTTP 状态与数值平台错误码，不记录 SDK 响应正文、凭据或目标身份。单个配置失败不会阻止其它配置推送。`/board push test` 使用与定时任务相同的主动发送流程，不能以被动回复成功代替主动能力验收。QQ 客户端的允许主动发送开关、平台能力与发送配额会影响实际送达。

APScheduler 每日 00:05 更新前一天缓存；明确开启推送后于 00:30 发送昨日榜单。时区默认 Asia/Shanghai。今日榜单由生成器 CLI 实时采集；用户资料查询所用的数据仍短暂缓存 30 秒。历史榜单只使用已积累的快照，缺少记录时明确提示，不捏造历史排名。上游总榜会注明不在日期边界附近抓取的排名来源。

## 配置与运行

`OBOT_PUBLIC_BASE_URL` 设置公网 HTTPS 根地址。不设置时绑定网页关闭。`OBOT_BOARD_BIND_TTL` 设置链接有效秒数，`OBOT_BOARD_TIMEZONE` 设置统计与定时时区。Caddy 将网页和 API 转发到同一后端，阻止公网 `/internal/*`，配置见 [网页工作台](web.md)。绑定表单使用 EP 的 Vue 页面，保留原链接路径和一次性语义。私聊 `/dashboard` 登录后可查看个人配置、切换打星显示及生成今日/昨日榜单；群主/群管可在工作台管理已授权群的非敏感显示设置，群绑定确认和推送开关仍在原群操作。

凭据使用 Fernet 加密后存入应用数据库，密钥保存在 LocalStore 的 `keys/credentials.key`。备份时需要同时保存数据库和密钥；数据库备份本身不能恢复凭据。绑定令牌只保存哈希，原始令牌置于网址片段并在页面加载后移除，不写入 URL 请求路径或访问日志。网页不回显密码，要求同源 JSON 请求。

HydroClient 使用独立异步 Cookie 会话，校验公网 DNS 地址并将实际 HTTPS 连接固定到校验过的 IP，保留原 Host 与 TLS SNI；拒绝跨站重定向。分页、响应大小和查询总时间有上限。访问受保护的管理接口触发 sudo 挑战后才提交密码确认，再重试原请求；不会主动提交没有待确认请求的 sudo。管理脚本刷新 problemStat/rp，异步等待结果，不阻塞事件循环。请求被拒绝时提示失败步骤和 HTTP 状态码，不回显账号或响应正文。

PeeperClient 只通过官方 `main.py` CLI 调用固定提交的生成器，不导入 `module.*`、继承渲染类或修改上游时钟、布局。协议为 `--config`、`--id`、`--output`、`--separate_cols` 及生成器的 JSON 缓存文件；版本查询也使用 `--version`。布局、配色和栏数完全由 Board 维护，OBot 不再添加分栏补丁。

- 今日／评测类型榜单使用 `--now --verdict AC或WA等简写`，由 CLI 登录并采集今日数据。OBot 提供昨日基准快照和显示配置；已有的异步 HydroClient 继续负责绑定验证、用户查询、历史快照积累。
- 昨日与历史榜单使用 `--full YYYY-MM-DD`，只读取传入的快照，不向 CLI 提供账号密码。缺失的历史数据不会通过今日数据补造。
- CLI 将日志和缓存写在程序旁边，因此每次调用在权限受限的临时目录中复制原样程序和资源，写入独立配置／缓存，完成后清理。密码仅在临时配置文件中，不进入参数、日志返回或图片处理进程；子进程环境不继承机器人配置。
- 联网 CLI 通过标准 `HTTPS_PROXY` 使用本机临时 CONNECT 代理，固定到已验证的公网 IP，仅允许当前站点的 HTTPS 端口，拒绝跨主机跳转；TLS 仍由 CLI 与站点直接协商。代理有总流量限制，整个任务受队列超时控制。取消／超时会终止并等待子进程退出。
- 上游会捕获异常后以 0 退出，故同时检查 `last_traceback.log` 的成功标记和输出文件；错误只记录固定诊断码，不返回上游日志或账号配置。

完成的 PNG 不追加 OBot 信息区，保留 Board 的布局、版权和渐变编号。独立图片处理进程仅校验格式与尺寸，尺寸合规时原字节交付，不重编码；不操作上游 section。读取 PNG 时限制 6400 万像素，最终输出超过 2400 万像素或最长边 8192 时等比例缩小。此限制发生在 CLI 生图之后，不再声称能预先测量上游画布。

CLI 使用标准 `TZ` 环境变量；Linux 部署遵循配置时区。Windows 下上游使用本地时区，且部分日期（例如正时区的 `1970-01-01`）可能触发原生时间转换错误；OBot 不对其打补丁，完整站点兼容性及这类限制由上游处理。固定版本升级时，运行 CLI 契约测试和真实站点验收。
