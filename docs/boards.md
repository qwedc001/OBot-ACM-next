# HydroOJ 训练榜单

Peeper Board Generator 以 Git submodule 接入 `third-party/peeper-board-generator`，固定提交 `e5764481984ce7f4291e0c17c064815f18bbb08f`（v1.2.5）。上游源码保持原样，榜单沿用其样式。初始化仓库时执行：

```sh
git submodule update --init --recursive
uv sync --extra render
```

升级生成器需要明确选择提交并更新主仓库的 gitlink，同时运行榜单渲染测试；不在启动时自动更新依赖。

## 绑定配置

私聊发送 `/board bind xxxOJ`，打开返回的一次性网页，填写 HydroOJ 公网 HTTPS 地址、管理员名称和密码。支持 `https://oj.example.com/d/team` 这样的域路径。配置名不区分大小写，支持字母、数字、汉字、下划线和短横线。

链接默认有效 15 分钟，打开和预览不会消耗链接；提交成功后失效。重新获取同名链接会作废之前的链接。登录验证失败可以重试，最多五次。个人与各群配置分别保存，查询不会回退到别人的配置。

群聊由群主、群管理员或机器人超管发起绑定。网页验证后先保存待确认配置；原发起人须在原群发送 `/board confirm xxxOJ` 才生效，确认时重新检查群管理权限。这样群中可见的链接本身不能直接替换群配置。普通群员可以查询已绑定的榜单。

网页还可设置排除 UID、排除某日期前注册的用户，以及是否显示打星用户。默认不排除用户，显示打星用户。账号必须具有读取训练记录和运行 Hydro 管理脚本的权限；当前支持密码登录，不支持额外的登录验证码或双因素认证流程。

## 使用

| 指令 | 作用 |
| --- | --- |
| `/board` | 根据当前场景和权限展示用法 |
| `/board list` | 列出当前对话可用配置 |
| `/board today [配置名]` | 今日榜单 |
| `/board yesterday [配置名]` | 昨日总榜 |
| `/board history YYYY-MM-DD [配置名]` | 指定日期的历史榜单 |
| `/board verdict WA [配置名]` | 今日指定评测类型的榜单 |
| `/board user id 用户ID [配置名]` | 私聊查询用户资料与今日提交统计 |
| `/board user name 用户名 [配置名]` | 私聊模糊匹配名字查询；含空格的名字使用引号 |
| `/board version` | 上游生成器版本 |
| `/board push on或off [配置名]` | 管理者开启或关闭本对话的每日推送 |
| `/board starred [on或off或toggle] [配置名]` | 管理者开启、关闭或切换打星用户显示；省略状态默认切换 |
| `/board unbind 配置名` | 管理者解除本对话绑定并清除相关缓存 |

评测类型包括 AC、WA、TLE、MLE、OLE、RE、CE、SE、FE、HKD。同一对话绑定多个配置时，查询需要指定名称。正式路径为 `/cp.board`，`/board` 是短别名；这是显式业务入口，不会自动注册其他目录或 QQ 指令面板。`/help cp` 可以查看模块说明。

`/board starred off xxxOJ` 隐藏打星用户，`/board starred on xxxOJ` 恢复显示；只有一个配置时可直接 `/board starred` 切换。设置持久保存在当前个人或群配置中，立即作用于下一次生成和每日推送，不需要重新绑定，也不会删除历史快照。

APScheduler 每日 00:05 更新前一天缓存；明确开启推送后于 00:30 发送昨日榜单。时区默认 Asia/Shanghai。今日数据短暂缓存 30 秒；历史榜单只使用已积累的快照，缺少记录时明确提示，不捏造历史排名。上游总榜会注明不在日期边界附近抓取的排名来源。

## 配置与运行

`OBOT_PUBLIC_BASE_URL` 设置公网 HTTPS 根地址，不设置时绑定网页关闭。`OBOT_BOARD_BIND_TTL` 设置链接有效秒数，`OBOT_BOARD_TIMEZONE` 设置统计与定时时区。Caddy 仅将 `/board/*` 转发到机器人，保留其他路径给后续 dashboard。

凭据使用 Fernet 加密后存入应用数据库，密钥保存在 LocalStore 的 `keys/credentials.key`。备份时需要同时保存数据库和密钥；数据库备份本身不能恢复凭据。绑定令牌只保存哈希，原始令牌置于网址片段并在页面加载后移除，不写入 URL 请求路径或访问日志。网页不回显密码，要求同源 JSON 请求。

HydroClient 使用独立异步 Cookie 会话，校验公网 DNS 地址并将实际 HTTPS 连接固定到校验过的 IP，保留原 Host 与 TLS SNI；拒绝跨站重定向。分页、响应大小和查询总时间有上限。访问受保护的管理接口触发 sudo 挑战后才提交密码确认，再重试原请求；不会主动提交没有待确认请求的 sudo。管理脚本刷新 problemStat/rp，异步等待结果，不阻塞事件循环。请求被拒绝时提示失败步骤和 HTTP 状态码，不回显账号或响应正文。

PeeperClient 经现有工作队列启动独立绘图进程，读取固定提交的 submodule 原程序。每次渲染使用临时目录，网络请求和密码不进入生成器；只传入榜单快照与显示配置。进程环境不传递机器人配置，超时或取消会结束该进程；图片复用 ArtifactClient 的权限与大小限制。渲染前检查画布不超过 6400 万像素；输出超过 2400 万像素或最长边 8192 时等比例缩小，保留完整内容。时钟适配位于 worker 中，保证 Windows 与服务器都使用配置时区，不修改上游源码。

迁移 `0002` 新增配置、一次性令牌和每日快照表，不导入旧机器人的账号密码或缓存。单元与合成测试覆盖真实原生 Matcher、绑定网页、权限隔离、并发提交/确认、SSRF 防护、定时推送开关和实际上游绘图；真实 Hydro 账号验证与 QQ 客户端收图需用用户填写的配置验收。
