# OBot 视觉设计

网页采用 [OBot-EP](https://github.com/Floating-Ocean/OBot-EP/tree/3e417697c31934008fd32ac7ca06f923b31ffd98) 的 Vue / Element Plus 架构，并保留 OBotLogo、主题状态与基础样式。原机器人参考 [OBot-ACM](https://github.com/Floating-Ocean/OBot-ACM) 的 Pixie 帮助与随机选择渲染，特别是 `src/render/pixie/render_pick_one.py` 的分类色和卡片层次。榜单继续由固定版本的 Peeper 绘制，不在网页复制绘图逻辑。

## 原有审美

原 OBot 的图形首先强调信息层次：重字标题、宽松留白、圆角画布。资料卡和 Peeper 用一张柔和的渐变承载正文，指标以字号与位置区分；帮助图按模块分栏，分组线、指令、说明逐级减弱。随机选择的类别色用于识别分类，不把每个字段装进彩色小卡片。

EP 的参考重点是工具入口、插件导航、主题变量和直接的操作流程。工作台保留灰白底、细边线与蓝绿品牌色，去掉页面光斑、重复英文小标题、口号和悬浮抬升。导航用选中下划线；功能入口写清实际用途。品牌标志保留原设计，不因扫描器误报重画。

## 网页约定

| 层次 | 约定 |
| --- | --- |
| 背景 | 浅色沿用 `#eceef4` / `#f6f7fb`，正文近黑 `#171a26`；暗色使用现有深蓝主题变量 |
| 品牌 | 蓝 `#5d90b2` 到绿 `#4e7f70`，用于标志与主要标题 |
| 卡片 | 8 / 12 / 16 px 圆角层级，实色表面与细边线，避免重复底框与彩色阴影 |
| 工具色 | 训练榜单绿色、指令目录紫色、运行状态蓝色；同一工具跨导航与卡片保持一致 |
| 文本 | 标题明确、正文简短、说明弱化；指令和参数使用等宽字体 |
| 交互 | 主操作清晰，次操作克制；加载、失败、空记录均有明确状态 |

首页使用工具卡片和简短说明，工具内部使用共同导航、页标题和内容容器。移动端改为单栏，表单两列收为一列，导航可横向滚动；页面本身不应横向溢出。390 px 手机与 1440 px 桌面纳入浏览器验收，支持系统主题、手动切换和减少动画偏好。

指令页用模块筛选与关键词搜索，搜索覆盖用法和示例；示例按钮直接复制，空结果可以清除筛选。模块内按行排列指令，别名用普通文字，避免一组字段套多层卡片。绑定页先显示必填内容，可选显示设置折叠。榜单生成后聚焦并滚动到带配置名、日期的预览，支持放大和下载；切换范围或刷新后不展示旧请求的图片。

帮助文案统一从 CommandSpec 供给文字、图片和网页：说明以“查看／查询／生成／上传”等动作开头，不加句末句号；用法只写指令语法，必填参数用 `<参数>`、可选参数用 `[参数]`、选项用 `a|b`，不把操作提示塞进参数。示例使用具体值，优先通过 `example_alias` 显示已注册的短别名；验证码等必须动态获取的值不编造示例。附图、引用消息、审核等要求写在说明中。文字帮助使用“指令 — 说明”后列出用法、别名、示例；图片以用法为标题，随后展示说明、别名、示例。子指令列表统一为“指令语法 — 动作说明”，并保留原有权限过滤。图片参数继续使用原版实线／虚线标记，不更改字号或布局。

## 图片配色

图片沿用原版 OBot/Peeper 的对角渐变、圆角画布、黑色外沿和 OPPOSans 字体。比赛列表与详情使用 easy-pixie 的 `pick_gradient_color()` 随机选取二色或三色渐变，保留原选择器的随机颜色顺序；帮助图使用原版亮度筛选（末端亮度 ≤ 0.75），叠加原版深色遮罩 `(9,9,9,238)`。同一次回复的测量、绘制、标题、分类强调色和分页共用一次选择，信息区直接使用所选对象的 `name`（`#编号 名称`）；编号对应锁定依赖自带的 uiGradients 目录，不固定为某一种配色。资料卡仍按段位配色，PickOne 保留按类别顺序分配的彩虹色。

| 使用位置 | 颜色依据 | 色值 |
| --- | --- | --- |
| Codeforces | 当前 Rating，分界 1200/1400/1600/1900/2100/2300/2400 | `#808080` / `#008000` / `#03A89E` / `#0000FF` / `#AA00AA` / `#FF8C00` / `#BBBB00` / `#FF0000` |
| AtCoder | 最高 Kyu/Dan/King 段位，与原版一致 | 灰、棕、绿、青、蓝、黄、橙、红；Kyu 每两级一色，1–2 Dan 黄、3–4 Dan 橙、5 Dan 及以上红 |
| 牛客 | 当前 Rating，分界 700/1100/1500/2000/2400/2800 | `#B4B4B4` / `#C177E7` / `#5EA1F4` / `#25BB9B` / `#FFD700` / `#FF8800` / `#FF020A` |

资料卡从 `#FCFCFC` 渐变到提亮 30% 的段位色，叠加白色遮罩（152/255）；保留原版 176 px 圆角头像、大号 Rating 色带、统一字号指标格、最近比赛／提交等分节。头像缺失时身份区自然收拢，不造首字母头像。恢复原版 1472 px 单栏画布，身份、Rating、指标、最近比赛和提交依次向下排列，保留既有字号与完整内容。数据由 Client 异步取回，View 不发网络请求。

帮助、比赛列表、PickOne、资料卡直接移植原 OBot 的 Pixie 绘制类，位于 `backend/framework/views/renderer/`。保留原来的字号、字重、行距、内外边距、图标尺寸、对齐、渐变方向、圆角与分栏实现；不在外围重新实现一套近似排版。

## 源码移植与接入边界

来源为 [Floating-Ocean/OBot-ACM](https://github.com/Floating-Ocean/OBot-ACM/tree/530f1518e9764a7c3ae194c5c0ccddec76e6d393/src/render) 的整个 `src/render` 文件夹（14 个文件），沿用 AGPL-3.0；原样副本独立提交后再做适配，保留 `html/`、`svg/`、`pixie/` 结构和原文件名。尚未迁移业务对应的绘制文件只保留源码，不加载或注册功能。资源从原项目 `lib/Render-Images` 复制到 `views/assets`。迁移调整集中在以下边界：

- `views/help.py`、`contests.py`、`pickone.py`、`profile.py` 与 `renderer/bindings.py`、`runtime.py` 适配当前数据模型。已接入的绘制代码不导入旧 `Constants`、业务存储或 botpy；其余原样保留的源码尚未接入。
- RenderClient 在独立子进程内加载原生绘图库并执行绘制；并发由共享 JobQueue 限制，进程之间不共享字体／图像缓存。头像、缩略图由现有 Client 提供字节，绘制时不联网；原版渲染器布局不因进程隔离而改写。
- 帮助使用已鉴权的指令目录；权限标签来自明确元数据，参数沿用当前 `<必填>` / `[选填]`。别名与示例放入原版说明文本区。
- 比赛使用同一查询快照的时间和北京时间格式化；ET 是已用时间比例 `(now-start)/duration`，从 0% 增长到 100%，沿用原编号下方的进度条与 `% ET` 文字，不表示剩余时间；列表按原版分状态编号，查询详情仍可使用名称或简称。原项目没有详情卡，其新增视图独立在 `contest_detail.py`。
- 保留原版随机选色与统一 CardFooter，信息区标注实际渐变编号和名称，只替换原版依赖全局版本号的生成信息；保留原 Tips 标题、提示文字、字体、间距和位置。PickOne 图鉴保留原版彩虹类别色、巨号计数、数量条与预览底板。
- 仅为当前用户自定义名称和参数文本补充栏内折行边界；ET 为 0% 时跳过零宽度填充，避免 Pixie 分配错误，仍绘制空轨道和 `0% ET`。字体、间距不为宽高比例做调整。

原版布局参数：比赛／帮助正文栏宽 916 px、栏间距 192 px；外框 32 px、左右留白 96 px、顶部留白 136 px、底部留白 152 px、区块间距 108 px。比赛标题 96 px、阶段标题 52 px、编号 78 px、比赛名 56 px、时间说明 32 px，比赛间距 108 px、阶段间距 128 px。帮助命令 52 px、参数 40 px、说明 28 px，指令间距 64 px、类别间距 136 px。资料卡和 PickOne 的专用参数保留在对应源码文件中。

比赛按最大状态组数量选择一至三栏（≤5／6–12／≥13），帮助最多四栏且不打乱模块顺序，PickOne 固定四列，资料卡单栏。共享基类保留原版连续分栏的高度均衡算法，不设目标比例。单图最大边长 8192 px、最多 2400 万像素；先尝试完整图，超限才按完整条目分页，单条过大时回退文字。第三方 Peeper 和原始媒体不应用此布局。

## 统一图片信息区

OBot 自行渲染的图片（如帮助图、资料卡）使用 `backend/framework/views/footer.py` 的 `CardFooter`，正文后保留间距和一条细分隔线，固定三行：

1. `OBot's Next ACM Bot · v版本号`：版本来自 `framework.__version__`，不在各渲染器手工填写。
2. `https://github.com/qwedc001/OBot-ACM-next`：公共项目地址，不读取部署 endpoint。
3. `© OBot-Next-Dev-Team · 配色`：段位色使用十六进制值，目录渐变使用编号和名称；多页帮助附页码。

主行 26 px，次行 22 px，行间距 10 px，分隔线后留 28 px；按实际内容宽度测量、必要时换行。浅色和深色画布只切换文字／分隔线透明度，结构保持一致。信息区不放用户标识、内部地址或凭据。

资料卡和帮助图在自己的画布中预留信息区高度，分页图每页都要包含。第三方工具生成的图片（如 Peeper Board）保留原有布局和署名，不追加 OBot 信息区。第三方 PNG 在发送限制内原字节交付，仅在超出尺寸限制时等比例缩小，不裁切、不加边框或水印。

设计复核使用 [kill-ai-slop](https://github.com/yetone/kill-ai-slop/tree/main/skill) 的扫描、人工判定与截图流程。扫描不是禁用渐变的规则：图片渐变由产品明确选用，原品牌标志、代码等宽字体、链接下划线和真实状态点均有用途，保留。

状态必须来自实际接口：没有机器人连接时显示“尚未连接”，没有处理记录时显示空状态，不填充演示统计。用户界面只展示当前可操作内容；权限检查、凭据与会话细节留在开发文档。绑定页不回显已有密码，提交后清空输入。

新增工具沿用主题变量、工具清单和共享外壳，只增加自己的视图与业务内容。EP 来源说明保留在样式和组件文件中，后续调整优先修改公共变量，避免每个工具维护另一套视觉系统。
