# OBot 视觉设计

网页采用 [OBot-EP](https://github.com/Floating-Ocean/OBot-EP/tree/3e417697c31934008fd32ac7ca06f923b31ffd98) 的 Vue / Element Plus 架构，并保留 OBotLogo、主题状态与基础样式。原机器人参考 [OBot-ACM](https://github.com/Floating-Ocean/OBot-ACM) 的 Pixie 帮助与随机选择渲染，特别是 `src/render/pixie/render_pick_one.py` 的分类色和卡片层次。榜单继续由固定版本的 Peeper 绘制，不在网页复制绘图逻辑。

## 原有审美

原 OBot 的图形首先强调信息层次：重字标题、宽松留白、圆角画布。资料卡和 Peeper 用一张柔和的渐变承载正文，指标以字号与位置区分；帮助图按模块分栏，分组线、指令、说明逐级减弱。随机选择的类别色用于识别分类，不把每个字段装进彩色小卡片。

EP 的参考重点是工具入口、插件导航、主题变量和直接的操作流程。工作台保留灰白底、细边线与蓝绿品牌色，去掉页面光斑、重复英文小标题、口号和悬浮抬升。导航用选中下划线；功能入口写清实际用途。品牌标志保留原设计，不因扫描器误报重画。

## 网页约定

| 层次 | 约定 |
| --- | --- |
| 背景 | 浅色沿用 `#eceef4` / `#f6f7fb`，正文近黑 `#171a26`；暗色使用现有深蓝主题变量 |
| 品牌 | 蓝 `#5d90b2` 到绿 `#4e7f70`，用于标志与主要标题 |
| 卡片 | 8 / 12 / 16 px 圆角层级，实色表面与细边线，避免重复底框与彩色阴影 |
| 工具色 | 训练榜单绿色、指令目录紫色、运行状态蓝色；同一工具跨导航与卡片保持一致 |
| 文本 | 标题明确、正文简短、说明弱化；指令和参数使用等宽字体 |
| 交互 | 主操作清晰，次操作克制；加载、失败、空记录均有明确状态 |

首页使用工具卡片和简短说明，工具内部使用共同导航、页标题和内容容器。移动端改为单栏，表单两列收为一列，导航可横向滚动；页面本身不应横向溢出。390 px 手机与 1440 px 桌面纳入浏览器验收，支持系统主题、手动切换和减少动画偏好。

指令页用模块筛选与关键词搜索，搜索覆盖用法和示例；示例按钮直接复制，空结果可以清除筛选。模块内按行排列指令，别名用普通文字，避免一组字段套多层卡片。绑定页先显示必填内容，可选显示设置折叠。榜单生成后聚焦并滚动到带配置名、日期的预览，支持放大和下载；切换范围或刷新后不展示旧请求的图片。

## 图片配色

图片沿用原版 OBot/Peeper 的对角渐变、圆角画布、黑色外沿和 OPPOSans 字体。资料卡按段位决定颜色；帮助图采用 Peeper/easy-pixie 0.0.10 的固定渐变 **#187 Decent**（`#4CA1AF` → `#C4E0E5`），叠加原版深色遮罩 `(9,9,9,238)`。固定编号不因上游目录重排改变。

| 使用位置 | 颜色依据 | 色值 |
| --- | --- | --- |
| Codeforces | 当前 Rating，分界 1200/1400/1600/1900/2100/2300/2400 | `#808080` / `#008000` / `#03A89E` / `#0000FF` / `#AA00AA` / `#FF8C00` / `#BBBB00` / `#FF0000` |
| AtCoder | 最高 Kyu/Dan/King 段位，与原版一致 | 灰、棕、绿、青、蓝、黄、橙、红；Kyu 每两级一色，1–2 Dan 黄、3–4 Dan 橙、5 Dan 及以上红 |
| 牛客 | 当前 Rating，分界 700/1100/1500/2000/2400/2800 | `#B4B4B4` / `#C177E7` / `#5EA1F4` / `#25BB9B` / `#FFD700` / `#FF8800` / `#FF020A` |

资料卡从 `#FCFCFC` 渐变到提亮 30% 的段位色，叠加白色遮罩（152/255）；使用原版 1472 px 画布、176 px 圆角头像、大号 Rating 色带、统一字号指标格、最近比赛／提交等分节。头像缺失时身份区自然收拢，不造首字母头像。数据由 Client 异步取回，View 不发网络请求。

帮助图参考原版 `render_help.py`：深色画布、浅强调色图标与大标题、模块标题色块和分隔线、指令／说明／用法／示例的字号层次。参数标注服从当前声明：`<必填>` 实线、`[选填]` 虚线，不沿用旧项目相反的括号含义。最多三栏，按实际测量高度选择最短栏，超长模块按指令边界分页。权限仍由指令执行的同一鉴权结果筛选，不从说明文字推断。

## 统一图片信息区

所有新生成图片使用 `backend/framework/views/footer.py` 的 `CardFooter`，正文后保留间距和一条细分隔线，固定三行：

1. `OBot's Next ACM Bot · v版本号`：版本来自 `framework.__version__`，不在各渲染器手工填写。
2. `https://github.com/qwedc001/OBot-ACM-next`：公共项目地址，不读取部署 endpoint。
3. `© OBot-Next-Dev-Team · 配色`：段位色使用十六进制值，目录渐变使用编号和名称；多页帮助附页码。

主行 26 px，次行 22 px，行间距 10 px，分隔线后留 28 px；按实际内容宽度测量、必要时换行。浅色和深色画布只切换文字／分隔线透明度，结构保持一致。信息区不放用户标识、内部地址或凭据。

资料卡和帮助图在自己的画布中预留信息区高度。Peeper 在隔离绘图进程中通过外层 section 适配追加相同信息区，保留原生成器说明、版权和渐变编号；submodule 不修改。信息区在尺寸检查和缩放之前计入画布，禁止事后覆盖正文或裁掉来源说明。后续新增渲染器必须复用此组件，分页图每页都要包含。

设计复核使用 [kill-ai-slop](https://github.com/yetone/kill-ai-slop/tree/main/skill) 的扫描、人工判定与截图流程。扫描不是禁用渐变的规则：图片渐变由产品明确选用，原品牌标志、代码等宽字体、链接下划线和真实状态点均有用途，保留。

状态必须来自实际接口：没有机器人连接时显示“尚未连接”，没有处理记录时显示空状态，不填充演示统计。用户界面只展示当前可操作内容；权限检查、凭据与会话细节留在开发文档。绑定页不回显已有密码，提交后清空输入。

新增工具沿用主题变量、工具清单和共享外壳，只增加自己的视图与业务内容。EP 来源说明保留在样式和组件文件中，后续调整优先修改公共变量，避免每个工具维护另一套视觉系统。
